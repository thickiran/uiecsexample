ECS-UI DATA FLOW:
=================

1. SUBSCENE INITIALIZATION:
   - ItemDataAuthoring GameObjects in SubScene bake into ECS ItemData entities at build/play time
   - InventoryDataUpdater.FindSubSceneItemData() queries for and caches these entities
   - ItemData entities provide max stack sizes and item properties for validation

2. RUNTIME INVENTORY CREATION:
   - InventoryDataUpdater.CreatePlayerInventory() creates runtime inventory entity
   - InventoryUIBridge.Initialize() is called with the new inventory entity
   - Bridge connects ECS inventory data to UI slot components

3. ECS → UI UPDATES:
   - User presses keyboard keys (1-6) → InventoryDataUpdater.AddItemToSlot()
   - Method validates against SubScene ItemData (max stack size, item properties)
   - ECS inventory buffer is updated with proper validation
   - InventoryChangedEvent is created
   - InventoryUISystem processes event and calls InventoryUIBridge.UpdateSlot()
   - UI slots update their visual representation

4. UI → ECS REQUESTS:
   - User drags item between slots
   - ItemSlotUI creates ItemMoveRequest ECS entity
   - InventoryManagementSystem processes the request using SubScene ItemData for validation
   - System updates ECS inventory data
   - InventoryChangedEvent is created
   - UI receives update and syncs visual state

5. DATA VALIDATION FLOW:
   - All item operations validate against SubScene ItemData entities
   - Max stack sizes enforced from ItemDataAuthoring components
   - Item properties (name, type, value) sourced from SubScene data
   - Consistent validation whether triggered by keyboard or drag-drop
